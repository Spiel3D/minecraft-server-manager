# Version 4.0.0 (cahier des charges V4)

Migration de base v4 (additive, copie automatique `panel.db.avant-v4`). Aucune nouvelle dépendance Python.

## RAM
- Plafond par serveur = RAM totale − réserve système, marge Java comprise : le maximum proposé peut réellement démarrer.
- Choix rapides 10 Go / 12 Go / Maximum, désactivés s'ils dépassent ; mêmes règles à la création et dans l'onglet Configuration.
- Résumé utilisée / attribuée / disponible / restante. Démarrage refusé si les serveurs allumés + celui-ci dépassent le budget.
- Réglages : réserve système et « Marge Java (%) » dans Paramètres (20 % par défaut : ≈ 11,2 Go max sur 16 Go ; 12 Go demande ~10 %).

## Création
- Partie, monde (seed, type), whitelist, accès cracké (confirmation explicite), distances, MOTD, joueurs… dès la création,
  plus tous les réglages de server.properties dans une section dépliable. Les fichiers propres au serveur (paper-global.yml,
  configs de mods) deviennent modifiables après le premier démarrage.
- Affichage « Type — Minecraft version » partout.

## Port principal 25565
- Bouton « Rendre principal » : réattribution automatique des ports, liste des joueurs qui seront déconnectés,
  redémarrage automatique après confirmation, vérification que le serveur répond, remise en état automatique en cas d'échec.
- L'ouverture du port sur la box reste manuelle.

## Notifications et crashs
- Cloche avec compteur : démarrage, ouverture aux joueurs, échec, arrêt normal/inattendu, crash, redémarrage auto,
  perte de réponse, RAM, disque, sauvegarde en échec, erreurs critiques des journaux.
- Rapport de crash : « Constaté dans les fichiers » séparé des « Causes possibles (non certaines) », mods à vérifier
  avec l'origine de l'indice, trace, console avant l'incident, crash-report téléchargeable.
- Webhooks Discord : événements et serveurs au choix, anti-spam. Bot Discord : prévu plus tard.

## Monitoring et statistiques
- Cases : disponibilité, TPS, latence serveur (ms par tick), CPU, RAM ; « n/d » avec la raison si le type ne le permet pas.
- « Ce PC ↔ panneau » : temps de réponse mesuré depuis le navigateur.
- Onglet Statistiques : historique 1 h / 24 h / 7 j, stats Minecraft par joueur, pic de joueurs, sessions.

## Mods
- Moteur de recherche Modrinth + CurseForge (clé à saisir dans Paramètres), filtres, fiches avec relations cliquables.
- Plan d'installation (dépendances, incompatibilités, mods client uniquement), empreintes vérifiées, progression, annulation, mises à jour.
- Éditeur de configuration TOML / JSON / YAML / properties / INI / cfg Forge : seule la valeur modifiée est réécrite, copie avant
  enregistrement, retour à l'original ; interfaces personnalisées déclaratives.

## Mondes SSD / HDD
- Mondes actifs sur le SSD (`/var/lib/minecraft-panel/ssd`), quota 50 Go réglable, au moins 10 Go toujours libres.
- Au démarrage d'un serveur sur le HDD : copie vers le SSD vérifiée fichier par fichier (taille + SHA-256), puis suppression
  de l'original. Si le quota est dépassé, le serveur ARRÊTÉ démarré il y a le plus longtemps repart sur le HDD.
  Un serveur allumé n'est jamais déplacé. Copie interrompue = dossier temporaire nettoyé, original intact.
- Archivage manuel d'un monde vers le HDD (ZIP vérifié + métadonnées et statistiques), restauration (le monde présent est
  renommé, jamais supprimé), sauvegarde optionnelle à l'arrêt propre.
- `uninstall.sh --purge-state` ne supprime jamais le dossier `ssd`. `tools/rollback.sh` refuse de revenir à une version
  antérieure tant que des serveurs sont sur le SSD (les remettre d'abord sur le disque dur).

## Interface
- Tableau de bord et « Mes serveurs » en deux catégories : En ligne (cases un peu plus grandes) puis Arrêtés.
- Cases légèrement agrandies, alignements et marges corrigés, même direction artistique.
